# ANTOLEOD — GitHub Profile Design Contract

> **Status:** Active source of truth  
> **Purpose:** Keep the public GitHub profile concise, professional, factual and visually consistent.

## 1. Identity

The profile represents **Juan Carlos Dioses / @antoleod** as an experienced IT professional who also builds automation, AI-assisted workflows and software products.

**Core positioning**

`Enterprise IT · Modern Workplace · Automation · Local AI · Product Engineering`

The profile must feel like a **modern technology portfolio**, not a CV pasted into GitHub and not a wall of badges.

## 2. Visual direction

**Theme:** Matrix-inspired, premium, minimal cyber aesthetic.

- Background: near-black / charcoal.
- Primary accent: Matrix neon green.
- Secondary accents: restrained cyan/blue only when useful.
- Typography: clean sans-serif + monospace for terminal details.
- Hero: cinematic Matrix-inspired digital-rain atmosphere, original artwork, no copied movie assets or characters.
- Visual hierarchy: hero → short identity → stack → featured work → activity.
- Mobile-first: everything must remain readable on a phone.
- Avoid excessive animations, badge walls, giant paragraphs and visual noise.

## 3. Hero contract

The hero is the strongest visual element.

**Primary message:**

> SAME HUMAN. BIGGER POSSIBILITIES.

**Supporting line:**

`IT · AUTOMATION · AI · REAL TOOLS`

**Optional terminal microcopy:**

`Observe → Learn → Build → Automate → Improve → Repeat`

The hero should communicate ambition and technical identity in under five seconds.

## 4. Content contract

The README should remain intentionally short.

### Required sections

1. Hero
2. Short introduction — maximum 3 lines
3. Tech stack
4. Selected / featured projects
5. Credentials — one compact line
6. GitHub activity
7. Short closing statement

### Forbidden patterns

- Full employment-history paragraphs.
- Repeating CV content.
- Unverified claims or invented metrics.
- Private project details.
- Personal phone number, home address or unnecessary personal data.
- More than ~5 featured projects.
- Long explanations where a label or one sentence works.

## 6. Featured-project policy

Featured projects must demonstrate quality, range and real building activity. Prefer projects that are public, understandable and visually presentable.

Current portfolio categories:

- **Oryxen** — automation / local AI / developer tooling.
- **IT Toolkit** — enterprise IT workflows and diagnostics.
- **GeoSpent** — Android / travel / maps.
- **PulseOne** — intelligent music experience.
- **EPSO Coach** — mobile-first learning/training product.

If a project is private, the public profile may describe the category/product at a high level but must not expose internal implementation details.

## 7. Quality bar — 10/10 checklist

Before every profile release:

- [ ] Hero renders correctly on desktop and mobile.
- [ ] No broken external images.
- [ ] README can be scanned in under 30 seconds.
- [ ] No section duplicates information.
- [ ] Every professional claim is factual.
- [ ] No sensitive/private data is exposed.
- [ ] Featured projects are current and intentional.
- [ ] Links work.
- [ ] Matrix aesthetic remains subtle and professional.
- [ ] Profile still looks credible to a recruiter, engineer and potential collaborator.

## 8. North star

> **Automate the repetitive. Focus on what really matters.**

The profile should leave one impression: **experienced in real-world IT, curious about what comes next, and consistently building useful things.**
